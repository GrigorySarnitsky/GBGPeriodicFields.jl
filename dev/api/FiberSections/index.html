FiberSections

GBGPeriodicFields.FiberSections — Module
FiberSections

Base-agnostic core of the package's fiber-bundle model.

A field (a section over a Grid3D) and a collection of off-grid point-values (a section over a PointSet) are both sections of a tensor bundle over a base. This module owns the part of the design that does not depend on which base is used, and it groups five families of machinery:

  • the fiber types — FiberVector, FiberTensor2, FiberTensor3 and FiberTensor4, StaticArrays aliases naming the value at one base point, together with fiber_shape. A fiber is base-agnostic by construction, so it belongs here and both the field and point layers take their fiber vocabulary from this module;
  • the AbstractFiberSection supertype, which both fields and point-values subtype;
  • the CPU-threading, fused-assignment primitive _assign! and its policy controls (with_threading, threading_cutoff, and set_threading_cutoff!);
  • the fiberwise-algebra code generators — the per-component builders behind operations such as dot, cross, and norm — written once here so that one set of generated kernels serves both field and point-value sections;
  • the fused fiberwise executor _fiberwise_pass! — one portable kernel and one slab-threaded CPU loop that run every stamped per-element values function, the execution route for multi-output fiberwise operations.

The base-specific halves live elsewhere. Fields (grid) and Points (point set) hold the concrete section types, the section-interface accessors (field_data, _vector_component_data, and _tensor2_component_data) and the broadcast styles, each extending the accessors for its own types, while FieldAlgebra and Points stamp the method tables from the builders here.

Fiber-section supertype

GBGPeriodicFields.FiberSections.AbstractFiberSection — Type
AbstractFiberSection{T, R}

Supertype of every section of the package's tensor bundle, so both fields (sections over a Grid3D, in physical-space or spectral representation) and point-values (sections over a PointSet) subtype it.

The parameter T<:AbstractFloat is the real scalar type, and R is the tensor order (0 scalar, 1 vector, 2 second-order tensor, and so on). The fiberwise algebra is rooted at this supertype because it is base-independent: it applies the same operation to the same fiber type whether the base is a structured grid or an unstructured point set.

Threading configuration

GBGPeriodicFields.FiberSections.threading_cutoff — Function
threading_cutoff()

Return the element count at or above which a CPU field assignment is split across Base.Threads workers rather than run serially. Here an assignment is a fused elementwise write into field storage — the _assign! primitive behind the broadcast route, and the same gate guards the fused CPU loops behind the algebra and the spectral operators, and the fixed-tree reductions. Two groups of operations sit outside the gate and thread by Threads.nthreads() regardless (see the warning on with_threading): the grid↔point transfer and the radial reductions. The count is measured as the destination array's length (grid points times fiber components), and it applies on the CPU only, since GPU arrays are never threaded. The default is 16384, and set_threading_cutoff! changes it.

source
GBGPeriodicFields.FiberSections.set_threading_cutoff! — Function
set_threading_cutoff!(n::Integer)

Set threading_cutoff to n and return it. A CPU field assignment whose destination has fewer than n elements then runs serially instead of threaded. Raise n to keep small operations off the thread pool, or lower it to thread smaller writes.

The cutoff is a single process-wide setting, unlike with_threading, whose override is dynamically scoped and therefore task-local. Set it once at startup rather than around a call.

source
GBGPeriodicFields.FiberSections.with_threading — Function
with_threading(f; enabled::Union{Nothing, Bool} = true)

Run f() with the CPU-threading decision forced to enabled, then restore the previous setting. Pass true or false to force the threaded or serial path, or nothing to follow the automatic nthreads()-based policy. The override is dynamically scoped and task-local, so it affects only f() and is restored afterwards, including on exceptions. Use enabled = false around a region that already parallelizes at a higher level, to avoid oversubscription.

Two groups of operations thread outside this override

The override (and the cutoff) governs the fused broadcast assignments, the fused CPU loops behind the algebra and the spectral operators (helmholtz_projection! included), and the fixed-tree reductions. Two groups of operations run as portable device-style kernels on every backend and partition by Threads.nthreads() directly, ignoring this setting: the grid↔point transfer (interpolate!/anterpolate!) and the radial reductions (radial_spectrum/radial_correlation) — the kernels with atomic or irregular access, which a gated loop cannot serve. To run those serially, start Julia with one thread.

GBGPeriodicFields.FiberSections._assign_threaded! — Method
_assign_threaded!(destination, broadcasted)

Thread a fused broadcast assignment by splitting the _slab_axis of destination into contiguous slabs and running the standard fused Broadcast.materialize! on each slab in its own task — the destination viewed to the slab, the Broadcasted tree rebuilt over _slice_broadcast_argument-sliced operands. Each slab therefore executes the same SIMD-vectorized broadcast kernel the serial path uses, only over a sub-range: fusion is preserved (no temporaries), and the result is bitwise-identical to serial, since each element is written exactly once from the same fused expression and no value crosses a slab boundary. This replaced a per-element CartesianIndex loop over the whole Broadcasted, which does not vectorize — measured at ~4.7× slower per core than materialize!, so threading inverted at low thread counts (2026-07-21; the finding and the numbers live with the benchmarks). The method falls back to serial when the axes do not match or an argument type is not sliceable, which is defensive because the field kernels always match and only build sliceable trees.

GBGPeriodicFields.FiberSections._check_owned_storage — Method
_check_owned_storage(data, what::AbstractString)

Reject storage that does not own its memory — a SubArray anywhere in the parent chain — so that two sections can share storage only by being backed by the same array.

A section over a view is not a construction this package has a use for. Nothing in the library builds one; there is no verb that returns one; and on a periodic domain it is not even meaningful, since a sub-block of a periodic base is not itself periodic and a component slice of a vector field is a coordinate projection rather than a scalar section (a component is obtained by contracting with a basis vector, which allocates).

What it did have was a silent wrong answer. A fused pass reads element $n$ and writes element $n$, which is safe when the destination IS an input and unsafe when one section's element $n$ is another's element $n + m$. Two overlapping views at different base offsets produced exactly that, in fourteen operations across three execution routes, with no error — and no contiguity test excludes it, since reshape(view(flat, 2:end), …) is densely strided and still overlaps at an offset. Ownership is the property that does exclude it.

The check is on ownership, not on layout: Array, CuArray, ROCArray and a reshape of any of them all own their memory and are accepted, so backend genericity (invariant 6) is untouched. Allocate with similar_field or similar_pointvalues rather than slicing a larger buffer.

GBGPeriodicFields.FiberSections._det_tensor_rhs — Method
_det_tensor_rhs(symbol, kind)

Build the right-hand side for the fiberwise determinant $\det(A) = \varepsilon_{ijk} A_{1i} A_{2j} A_{3k}$, the third principal invariant $I_3$ of the $3\times3$ tensor symbol (kind is :field or :fiber), expanded by cofactors along the first row:

\[\det(A) = A_{11}(A_{22}A_{33} - A_{23}A_{32}) - A_{12}(A_{21}A_{33} - A_{23}A_{31}) + A_{13}(A_{21}A_{32} - A_{22}A_{31}).\]

It feeds _scalar_kernel_body. Unlike the linear _trace_tensor_rhs, the determinant is cubic in the components (a homogeneous degree-3 form), so it is a nonlinear operation and is generated for physical-space representation only.

GBGPeriodicFields.FiberSections._fiberwise_pass! — Method
_fiberwise_pass!(backend, f, targets, arrays, constants, α, β)

Run one fused fiberwise pass — every target element receives α * f(element values..., constants...), plus β times its prior value when the accumulate is requested — over the common linear index range of the participating storage. Here f is a pure scalar values function: it takes one scalar per entry of arrays (that array's element at the running index) followed by the fiber constants verbatim, and returns the tuple of output values written to targets. Every array element is read once and every output written once, and all of an element's reads happen before its writes, so a target may alias a source array — the index-shuffle guard is unnecessary on this path. The generic method launches the _fiberwise_values_kernel! device kernel on the backend; the KernelAbstractions.CPU method runs a slab-threaded @simd loop over the linear range (component views are contiguous, so linear indexing is stride-1) through the same _use_threads gate as the broadcast route, bitwise-identical to serial because each element is written once from the same expression.

GBGPeriodicFields.FiberSections._slice_broadcast_argument — Method
_slice_broadcast_argument(argument, axis::Val, slab)

Restrict one broadcast argument to the slab range of broadcast axis axis. An array spanning that axis is viewed to the slab (a view re-bases its axes, so all sliced operands land on matching OneTo axes); an array with a singleton or missing axis passes through unchanged (broadcasting extrudes it exactly as in the full assignment); a nested Broadcasted is rebuilt over its sliced arguments; scalars and Refs are shape-free and pass through. The axis is a Val so the whole recursive slice specializes: with it a runtime Int would leave every view and rebuilt node un-inferred, boxing kilobytes per slab where the specialized form allocates only the small wrapper objects themselves.

GBGPeriodicFields.FiberSections._to_broadcasted — Method
_to_broadcasted(expr)

Rewrite a dotted expression — an infix dotted operator such as a .* b .+ c, or a broadcast call such as f.(x) — into the equivalent lazy Base.Broadcast.broadcasted(...) tree, recursing into operands and leaving non-broadcast subexpressions untouched. GBGPeriodicFields.FiberSections._undot — Method
_undot(expr)

Lower a dotted formula expression to its per-element form: dotted operators (.+, .*, …) lose their dots and dotted calls f.(x) become plain calls, recursively. GBGPeriodicFields.FiberSections._vector_kernel_body — Method
_vector_kernel_body(formula; alpha_beta::Bool)

Build the body of a vector-valued kernel, writing destination_i .= formula(i) for i in 1:3, where formula(i) is the per-component expression. With alpha_beta = true it emits the five-argument destination = α * formula + β * destination form and branches on iszero(β_value), so the pure-overwrite path stays allocation-free. The body ends in return destination and is spliced into a function that binds destination (and, when alpha_beta is set, α_value and β_value).
