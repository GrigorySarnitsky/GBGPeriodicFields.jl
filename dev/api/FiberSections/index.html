FiberSections

GBGPeriodicFields.FiberSections — Module
FiberSections

Base-agnostic core of the package's fiber-bundle model.

A field (a section over a Grid3D) and a collection of off-grid point-values (a section over a PointSet) are both sections of a tensor bundle over a base. This module owns the part of the design that does not depend on which base is used, and it groups three families of contributor-facing machinery:

  • the AbstractFiberSection supertype, which both fields and point-values subtype;
  • the CPU-threading, fused-assignment primitive _assign! and its policy controls (with_threading, threading_cutoff, and set_threading_cutoff!);
  • the fiberwise-algebra code generators — the per-component builders behind operations such as dot, cross, and norm — written once here so that one set of generated kernels serves both field and point-value sections.

The base-specific halves live elsewhere. Fields (grid) and Points (point set) hold the concrete types, the section-interface accessors (field_data, _vector_component_data, and _tensor2_component_data), fiber_shape, and the broadcast styles, each extending the accessors for its own types, while FieldAlgebra and Points stamp the method tables from the builders here.

Fiber-section supertype

GBGPeriodicFields.FiberSections.AbstractFiberSection — Type
AbstractFiberSection{T, R}

Supertype of every section of the package's tensor bundle, so both fields (sections over a Grid3D, in physical-space or spectral representation) and point-values (sections over a PointSet) subtype it.

The parameter T<:AbstractFloat is the real scalar type, and R is the tensor order (0 scalar, 1 vector, 2 second-order tensor, and so on). The fiberwise algebra is rooted at this supertype because it is base-independent: it applies the same operation to the same fiber type whether the base is a structured grid or an unstructured point set.

Threading configuration

GBGPeriodicFields.FiberSections.threading_cutoff — Function
threading_cutoff()

Return the element count at or above which a CPU field assignment is split across Base.Threads workers rather than run serially. Here an assignment is a fused elementwise write into field storage — the _assign! primitive behind every in-place operation, whose docstring carries the full policy. The count is measured as the destination array's length (grid points times fiber components), and it applies on the CPU only, since GPU arrays are never threaded. The default is 16384, and set_threading_cutoff! changes it.

source
GBGPeriodicFields.FiberSections.set_threading_cutoff! — Function
set_threading_cutoff!(n)

Set threading_cutoff to n and return it. A CPU field assignment whose destination has fewer than n elements then runs serially instead of threaded. Raise n to keep small operations off the thread pool, or lower it to thread smaller writes.

source
GBGPeriodicFields.FiberSections.with_threading — Function
with_threading(f; enabled = true)

Run f() with the CPU-threading decision forced to enabled, then restore the previous setting. Pass true or false to force the threaded or serial path, or nothing to follow the automatic nthreads()-based policy. The override is dynamically scoped and task-local, so it affects only f() and is restored afterwards, including on exceptions. Use enabled = false around a region that already parallelizes at a higher level, to avoid oversubscription.

Internal API

The CPU-threading primitives and the fiberwise-algebra code generators — not part of the public interface, documented for contributors extending the package's algebra.

GBGPeriodicFields.FiberSections._SERIAL_CUTOFF — Constant
_SERIAL_CUTOFF

Element count below which an assignment runs serially regardless of thread count. Threading overhead is not worth it for small arrays, and this cutoff also exempts the one-element zero-mode views. The assignment hot path reads it, and set_threading_cutoff! sets it.

source
GBGPeriodicFields.FiberSections._THREADING_OVERRIDE — Constant
_THREADING_OVERRIDE

Task-local override for the threading decision. A value of nothing follows Threads.nthreads(), while true or false forces the threaded or serial path. with_threading sets it within a dynamic scope.

GBGPeriodicFields.FiberSections._assign! — Method
_assign!(destination, broadcasted)

Materialize the lazy broadcasted expression into destination, threading over chunks on the CPU when _use_threads allows. The generic method is the standard fused Broadcast.materialize!, the safe polarity that keeps GPU arrays and unknown array wrappers on their normal broadcast path with no scalar indexing. Only dense Arrays and Array-backed SubArrays take the threaded path.

source
GBGPeriodicFields.FiberSections._assign_threaded! — Method
_assign_threaded!(destination, broadcasted)

Thread a fused broadcast assignment over contiguous chunks of destination's linear index range. Each task converts its linear indices to Cartesian ones and writes the corresponding broadcast elements, so fusion is preserved (one Broadcasted tree, no temporaries) and the result is bitwise-identical to serial, since each index is written by exactly one task. Cartesian indexing of the Broadcasted works on every supported Julia version and correctly remaps singleton operand axes, whereas linear indexing of a multidimensional Broadcasted is only supported on Julia 1.12 or newer. The method falls back to serial when the axes do not match, which is defensive because the field kernels always match.

GBGPeriodicFields.FiberSections._det_tensor_rhs — Method
_det_tensor_rhs(symbol, kind)

Build the right-hand side for the fiberwise determinant $\det(A) = \varepsilon_{ijk} A_{1i} A_{2j} A_{3k}$, the third principal invariant $I_3$ of the $3\times3$ tensor symbol (kind is :field or :fiber), expanded by cofactors along the first row:

\[\det(A) = A_{11}(A_{22}A_{33} - A_{23}A_{32}) - A_{12}(A_{21}A_{33} - A_{23}A_{31}) + A_{13}(A_{21}A_{32} - A_{22}A_{31}).\]

It feeds _scalar_kernel_body. Unlike the linear _trace_tensor_rhs, the determinant is cubic in the components (a homogeneous degree-3 form), so it is a nonlinear operation and is generated for physical-space representation only.

GBGPeriodicFields.FiberSections._sym_kernel_body — Method
_sym_kernel_body()

Build the body of the symmetric-part kernel $\operatorname{sym}(A) = \tfrac{1}{2} (A + A^\top)$ for a section argument named A, writing into destination. GBGPeriodicFields.FiberSections._to_broadcasted — Method
_to_broadcasted(expr)

Rewrite a dotted expression — an infix dotted operator such as a .* b .+ c, or a broadcast call such as f.(x) — into the equivalent lazy Base.Broadcast.broadcasted(...) tree, recursing into operands and leaving non-broadcast subexpressions untouched. This codegen helper lets generated and hand-written kernels route a fused assignment through _assign! without materializing intermediates, so fusion is preserved.

source
GBGPeriodicFields.FiberSections._trace_tensor_rhs — Method
_trace_tensor_rhs(symbol, kind)

Build the right-hand side for the fiberwise trace $\operatorname{tr}(A) = A_{ii} = A_{11} + A_{22} + A_{33}$, the sum of the diagonal components of the tensor symbol (kind is :field or :fiber). It feeds _scalar_kernel_body, and _dev_kernel_body reuses it for the trace it subtracts. The trace is linear, so the same body serves both physical-space and spectral representation.

GBGPeriodicFields.FiberSections._vector_kernel_body — Method
_vector_kernel_body(formula; alpha_beta::Bool)

Build the body of a vector-valued kernel, writing destination_i .= formula(i) for i in 1:3, where formula(i) is the per-component expression. With alpha_beta = true it emits the five-argument destination = α * formula + β * destination form and branches on iszero(β_value), so the pure-overwrite path stays allocation-free. The body ends in return destination and is spliced into a function that binds destination (and, when alpha_beta is set, α_value and β_value).

GBGPeriodicFields.FiberSections.section_scalar_type — Method
section_scalar_type(section::AbstractFiberSection)

Return the real scalar type T of any section. Because it is defined once on AbstractFiberSection{T}, it yields the real T for fields (including spectral fields, whose data is Complex{T}) and for point-values alike, which lets the shared sym/skew/dev kernels obtain T without dispatching on the concrete base.

GBGPeriodicFields.FiberSections.@_assign! — Macro
@_assign!(destination .= rhs)

Replace a fused broadcast assignment with a threaded one: rewrite rhs to a lazy broadcast tree (via _to_broadcasted) and assign it through _assign!, so the write threads on the CPU. Use it in hand-written kernels in place of .=, and note that _assign! must be in scope at the call site.
