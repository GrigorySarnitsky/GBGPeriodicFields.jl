Fields

GBGPeriodicFields.Fields — Module
Fields

Field representation and transform core for scalar, vector, and tensor fields on three-dimensional rectangular periodic domains.

This module defines grids, Cartesian fiber types, Fourier-layout conventions, field types for physical-space representation and real-to-complex spectral representation, FFT transform plans, and storage-wise broadcasting designed for CPU and GPU array backends.

source

The Fields module defines the field objects and their storage. A field is a physical object; the physical and spectral types (e.g. ScalarFieldPhysical and ScalarFieldSpectral) are two representations of the same field. It provides:

  • Grids and layout — Grid3D for the periodic domain geometry and RealFourierLayout for the real-to-complex transform layout.
  • Fiber types — the Cartesian fiber types FiberVector, FiberTensor2, FiberTensor3, FiberTensor4 (StaticArrays aliases), elements of the fiber $(\mathbb R^3)^{\otimes R}$ for tensor order $R$.
  • Field types — scalar, vector, and second-order tensor fields, each in physical-space and spectral representation.
  • Transforms — FieldTransformPlans and to_physical(!) / to_spectral(!). The allocating forms preserve their input; the in-place ! forms may overwrite the source (a property of the real FFT — see their docstrings).
  • Spectral multipliers — FieldSpectralMultipliers, the wavenumber arrays used by the spectral differential operators.
  • Broadcasting — fields broadcast storage-wise and representation-preserving: a dotted assignment writes into the destination field's storage, while an out-of-place dotted expression allocates a compatible field in the same representation. Physical and spectral representations cannot be mixed in one broadcast.

GBGPeriodicFields.Fields.FieldSpectralMultipliers — Type
FieldSpectralMultipliers(
  grid::Grid3D{T},
  fourier_layout::RealFourierLayout,
  wavenumber_1, wavenumber_2, wavenumber_3,
  squared_wavenumber_1, squared_wavenumber_2, squared_wavenumber_3,
) where {T<:AbstractFloat}

FieldSpectralMultipliers(
  field::AbstractFieldSpectral{T},
  wavenumber_1, wavenumber_2, wavenumber_3,
  squared_wavenumber_1, squared_wavenumber_2, squared_wavenumber_3,
) where {T<:AbstractFloat}

One-dimensional Fourier wavenumber arrays for coefficientwise spectral operators such as derivatives, the Laplacian, and the Helmholtz projection.

The fields are

  • grid, fourier_layout: the Grid3D and RealFourierLayout the multipliers were built for.
  • wavenumber_1, wavenumber_2, wavenumber_3: the per-axis physical (angular) wavenumbers $k$ along each axis, used for first derivatives via multiplication by $\mathrm{i} k$.
  • squared_wavenumber_1, squared_wavenumber_2, squared_wavenumber_3: per-axis squared wavenumbers, used for the Laplacian via multiplication by $-k^2$.

Each array runs along one spatial axis in the FFT frequency ordering of fourier_layout; the half axis fourier_layout.fft_dims[1] stores only the nonnegative frequencies. The arrays must live on storage (CPU or GPU) matching the fields the multipliers are applied to.

These two constructors are explicit: you supply both the wavenumbers and the squared wavenumbers, and only their lengths are checked. The two array families are stored independently rather than squaring one to obtain the other, because on even grids they use different conventions for the Nyquist mode (the highest representable frequency). A convenience constructor FieldSpectralMultipliers(field) builds both families from the field's grid and layout with the correct Nyquist treatment; it is documented separately below.

GBGPeriodicFields.Fields.FieldSpectralMultipliers — Method
FieldSpectralMultipliers(field::AbstractFieldSpectral{T}) where {T<:AbstractFloat}

Build the spectral multipliers from the grid and Fourier layout of field, allocated on the field's storage backend.

The wavenumbers are the physical angular wavenumbers $k = 2\pi n / L$ along each axis, where $L$ is the domain length and $n$ runs over the FFT frequency indices. On an even-length axis the highest stored mode is the Nyquist mode: its first-derivative wavenumber is set to zero, so that derivatives of real fields stay real, while its squared wavenumber keeps the true $k^2$, so that the Laplacian and Poisson-type solves stay correct. On an odd-length axis there is no exact Nyquist mode and no special treatment is applied.

GBGPeriodicFields.Fields.FieldTransformPlans — Type
FieldTransformPlans(
  physical::AbstractFieldPhysical{T, R},
  spectral::AbstractFieldSpectral{T, R};
  fft_flags = nothing,
  fft_timelimit = Inf,
) where {T<:AbstractFloat, R}

Forward and inverse FFT plans connecting compatible fields represented in physical and spectral space.

Here physical provides the real-space storage array, spectral provides the real-to-complex Fourier coefficient array, fft_flags is an optional backend-specific FFT planner flag, and fft_timelimit is the planner time limit used when fft_flags is provided. Only the spatial dimensions field_layout(physical).fft_dims are transformed; tensor-fiber dimensions are left untransformed.

The fields are

  • grid::G: the Grid3D for which the plans were constructed.
  • fourier_layout::L: the RealFourierLayout for which the plans were constructed.
  • plan_forward_fft::PF: the plan transforming physical values to spectral coefficients.
  • plan_inverse_fft::PI: the plan transforming spectral coefficients to physical values.

The plans are backend-, array-type-, scalar-type-, and tensor-order-specific; construct a separate FieldTransformPlans object for each CPU/GPU backend and field tensor order.

GBGPeriodicFields.Fields.RealFourierLayout — Type
RealFourierLayout()
RealFourierLayout(fft_dims::NTuple{3, Int})

Layout convention for three-dimensional real-to-complex Fourier transforms.

Here fft_dims is the tuple of transformed dimensions passed to the FFT planner. The main role of the ordering is to specify the real-FFT half dimension: in dimension fft_dims[1], only the nonnegative frequencies are represented, while the other dimensions use the full complex FFT frequency ordering.

The zero-argument constructor uses fft_dims = (1, 2, 3).

Scalar field in spectral representation, stored as its nonredundant real-to-complex Fourier coefficients.

Here fourier_coefficients contains the complex Fourier coefficients in real-FFT storage, grid is the Grid3D associated with the physical domain, and fourier_layout is the RealFourierLayout specifying the transformed dimensions and the real-FFT half dimension.

The coefficient array has shape spectral_field_shape(grid, fourier_layout, Val(0)). The dimension fourier_layout.fft_dims[1] is the real-FFT half dimension.

Broadcasting over scalar fields in spectral representation is lifted to fourier_coefficients. Thus dotted assignments such as @. destination = a - b + c write into destination.fourier_coefficients, while field-valued out-of-place dotted expressions return a new ScalarFieldSpectral. All such operations are coefficientwise; for example, .* does not represent a pseudospectral product of scalar fields.

The two-argument constructor uses the default RealFourierLayout() for the layout.

GBGPeriodicFields.Fields.to_physical! — Method
to_physical!(
  physical::AbstractFieldPhysical{T, R},
  spectral::AbstractFieldSpectral{T, R},
  transform_plans::FieldTransformPlans{T, R},
) where {T<:AbstractFloat, R}

Transform a field from spectral space to physical space in-place.

Here physical is the destination, spectral is the source, and transform_plans provides the inverse FFT plan.

The inverse transform uses spectral as scratch space and may overwrite it: on return its coefficients are left in an undefined state (the FFTW CPU backend destroys them — complex-to-real transforms have no input-preserving algorithm in the multidimensional case; some GPU backends happen to preserve them, but this is not guaranteed). Use the allocating to_physical when spectral must be preserved.

Returns the modified destination field.

Transform a field from physical space to spectral space in-place.

GBGPeriodicFields.Fields._squared_wavenumber_broadcast — Method
_squared_wavenumber_broadcast(multipliers::FieldSpectralMultipliers)

Return the total squared wavenumber $|k|^2 = k_1^2 + k_2^2 + k_3^2$ as a lazy Broadcasted over the three per-axis squared-wavenumber vectors (reshaped to the three spatial dimensions). Used by the Laplacian, inverse Laplacian, and Helmholtz projection.

Lazy on purpose: returning the unfused Broadcasted lets callers compose it into their own broadcasts (-|k|² ŝ, ŝ - kᵢ kⱼŝⱼ/|k|², …) without ever materializing the $O(N^3)$ array. That keeps those operators allocation-free in place — important in allocating hot loops, and on the GPU where a per-call $|k|^2$ scratch would otherwise grow the memory pool every step.
