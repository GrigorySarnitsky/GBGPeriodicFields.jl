GBGPeriodicFields.Fields — Module
Fields

Field representation and transform core for scalar, vector, and tensor fields on three-dimensional rectangular periodic domains.

This module defines grids, Cartesian fiber types, Fourier-layout conventions, field types for physical-space representation and real-to-complex spectral representation, FFT transform plans, and storage-wise broadcasting designed for CPU and GPU array backends.

GBGPeriodicFields.Fields.Grid3D — Type
Grid3D(
  grid_size::NTuple{3, Int},
  domain_size::NTuple{3, T},
  grid_spacing::NTuple{3, T},
  origin::NTuple{3, T},
) where {T<:AbstractFloat}

Grid3D(
  grid_size::NTuple{3, Int},
  domain_size::NTuple{3, T};
  origin::NTuple{3, T} = (zero(T), zero(T), zero(T)),
) where {T<:AbstractFloat}

Uniform three-dimensional grid for a periodic rectangular domain.

The fields are

  • grid_size::NTuple{3, Int}: the number of grid points in each spatial direction.
  • domain_size::NTuple{3, T}: the length of the domain in each spatial direction.
  • grid_spacing::NTuple{3, T}: the spacing between adjacent grid points in each spatial direction.
  • origin::NTuple{3, T}: the physical coordinates of the first grid point.

The two-argument constructor computes grid_spacing = domain_size ./ grid_size.

GBGPeriodicFields.Fields.RealFourierLayout — Type
RealFourierLayout()
RealFourierLayout(fft_dims::NTuple{3, Int})

Layout convention for three-dimensional real-to-complex Fourier transforms.

Here fft_dims is the tuple of transformed dimensions passed to the FFT planner. The main role of the ordering is to specify the real-FFT half dimension: in dimension fft_dims[1], only the nonnegative frequencies are represented, while the other dimensions use the full complex FFT frequency ordering.

The zero-argument constructor uses fft_dims = (1, 2, 3).

GBGPeriodicFields.Fields.rfft_shape — Function
rfft_shape(grid_size::NTuple{3, Int}, fft_dims::NTuple{3, Int})

Return the shape of the nonredundant real-to-complex Fourier representation of a three-dimensional real field.

Here grid_size is the physical grid size and fft_dims is the order of transformed dimensions. The dimension fft_dims[1] is the real-FFT half dimension: it is stored with length grid_size[fft_dims[1]] ÷ 2 + 1, while the other dimensions keep their physical-grid lengths.

Returns a three-tuple giving the spectral array size.

GBGPeriodicFields.Fields.AbstractFieldPhysical — Type
AbstractFieldPhysical{T, R}

Abstract supertype for fields represented by values in physical space.

Here T<:AbstractFloat is the real scalar type associated with the field and R is the tensor order stored as an integer value parameter. Concrete subtypes provide the actual storage and metadata. Field types

GBGPeriodicFields.Fields.ScalarFieldPhysical — Type
ScalarFieldPhysical(
  values_at_grid::AbstractArray{T, 3},
  grid::Grid3D{T},
  fourier_layout::RealFourierLayout,
) where {T<:AbstractFloat}

ScalarFieldPhysical(
  values_at_grid::AbstractArray{T, 3},
  grid::Grid3D{T},
) where {T<:AbstractFloat}

Scalar field in physical-space representation, stored as its values on a three-dimensional physical grid.

Here values_at_grid contains the real scalar values, grid is the Grid3D on which the values are sampled, and fourier_layout is the RealFourierLayout used when transforming the field.

Broadcasting over scalar fields in physical-space representation is lifted to values_at_grid. Thus dotted assignments such as @. destination = a - b + c write into destination.values_at_grid, while field-valued out-of-place dotted expressions return a new ScalarFieldPhysical.

The two-argument constructor uses the default RealFourierLayout() for the layout.

source
GBGPeriodicFields.Fields.ScalarFieldSpectral — Type
ScalarFieldSpectral(
  fourier_coefficients::AbstractArray{Complex{T}, 3},
  grid::Grid3D{T},
  fourier_layout::RealFourierLayout,
) where {T<:AbstractFloat}

ScalarFieldSpectral(
  fourier_coefficients::AbstractArray{Complex{T}, 3},
  grid::Grid3D{T},
) where {T<:AbstractFloat}

Scalar field in spectral representation, stored as its nonredundant real-to-complex Fourier coefficients.

Here fourier_coefficients contains the complex Fourier coefficients in real-FFT storage, grid is the Grid3D associated with the physical domain, and fourier_layout is the RealFourierLayout specifying the transformed dimensions and the real-FFT half dimension.

The coefficient array has shape spectral_field_shape(grid, fourier_layout, Val(0)). The dimension fourier_layout.fft_dims[1] is the real-FFT half dimension.

Broadcasting over scalar fields in spectral representation is lifted to fourier_coefficients. Thus dotted assignments such as @. destination = a - b + c write into destination.fourier_coefficients, while field-valued out-of-place dotted expressions return a new ScalarFieldSpectral. All such operations are coefficientwise; for example, .* does not represent a pseudospectral product of scalar fields.

The two-argument constructor uses the default RealFourierLayout() for the layout.

Transforming between representations

GBGPeriodicFields.Fields.FieldTransforms — Type
FieldTransforms(
  physical::AbstractFieldPhysical{T, R},
  spectral::AbstractFieldSpectral{T, R};
  fft_flags = nothing,
  fft_timelimit = Inf,
) where {T<:AbstractFloat, R}

Forward and inverse FFT plans connecting compatible fields represented in physical and spectral space.

Here physical provides the real-space storage array, spectral provides the real-to-complex Fourier coefficient array, fft_flags is an optional backend-specific FFT planner flag, and fft_timelimit is the planner time limit used when fft_flags is provided. Only the spatial dimensions field_layout(physical).fft_dims are transformed; tensor-fiber dimensions are left untransformed.

The fields are

  • grid::G: the Grid3D for which the plans were constructed.
  • fourier_layout::L: the RealFourierLayout for which the plans were constructed.
  • plan_forward_fft::PF: the plan transforming physical values to spectral coefficients.
  • plan_inverse_fft::PI: the plan transforming spectral coefficients to physical values.

The plans are backend-, array-type-, scalar-type-, and tensor-order-specific; construct a separate FieldTransforms object for each CPU/GPU backend and field tensor order.

Broadcasting

Field broadcasting is storage-wise and representation-preserving. Dotted assignments write into the destination field storage, while field-valued out-of-place dotted expressions allocate a compatible field in the same representation.
