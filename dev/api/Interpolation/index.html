Interpolation

GBGPeriodicFields.Interpolation — Module
Interpolation

Transfer between the grid sections of Fields and the point sections of Points: evaluating a field at off-grid positions, and depositing per-point quantities back onto the grid. The two operations are formal adjoints of each other. The transfer kernels are not yet implemented: this module currently records only the design (its docstring). The planned method (the Lalescu local splines), terminology, and GPU rationale are in docs/ARCHITECTURE.md §10; the point-value data types and their fiberwise algebra live in the Points module.

Planned API

  • Interpolation (grid to point, gather): interpolate(f, xs[, scheme]) / in-place interpolate!(out, f, xs[, scheme]), plus the callable f(x) (and its broadcast f.(xs)) as the ergonomic face of interpolate.
  • Anterpolation (point to grid, scatter): anterpolate(grid, xs, qs[, scheme]) / in-place anterpolate!(field, xs, qs[, scheme]), with a five-argument α/β form (β = 0 overwrite, β ≠ 0 accumulate, the mul! convention; accumulation is the common case for the scatter).

interpolate / anterpolate! are the symmetric named pair (the operators 𝓘 = W / 𝓘* = Wᵀ); only interpolation also carries the pointwise callable f(x), because evaluation is pointwise while its adjoint is not. Both directions share one scheme (the same weights) — which is what makes them an adjoint pair.

Why interpolation and anterpolation are adjoint: the function–measure duality

𝓘 : G → P and 𝓘* : P → G satisfy ⟨𝓘 f, q⟩_P = ⟨f, 𝓘* q⟩_G, a duality between functions (which you evaluate) and measures (which you integrate against):

  • evaluation is pairing with a Dirac mass, f(x) = ⟨δₓ, f⟩, so (𝓘 f)ₚ = ⟨δ_{xₚ}, f⟩ = f(xₚ);
  • its adjoint cannot be pointwise — it returns a measure, a sum of point masses 𝓘* q = Σₚ qₚ δ_{xₚ}, regularized by the stencil kernel to Σₚ qₚ β(·−xₚ), a point source density.

Hence the API asymmetry: you evaluate functions (f(x) returns a value) but accumulate measures (anterpolate! adds a source density onto a field); there is no pointwise f(x) = q. Discretely, with G = ℝᴺ (N grid nodes) and P = ℝᴹ (M points), interpolation is the matrix 𝓘 = W (Wₚₙ = βₙ(xₚ)) and anterpolation its transpose 𝓘* = Wᵀ. With shared partition-of-unity weights (𝓘 𝟙 = 𝟙, i.e. Σₙ Wₚₙ = 1), anterpolation is the exact transpose of interpolation and the total deposited quantity is conserved,

Σₙ (𝓘* q)ₙ = ⟨𝟙, 𝓘* q⟩ = ⟨𝓘 𝟙, q⟩ = ⟨𝟙, q⟩ = Σₚ qₚ,

which is mandatory for the two-way-coupled parcel application (total water mass and latent heat conserved). This holds only when both directions use the same weights, so the design fixes anterpolation as the transpose/adjoint of whatever interpolation scheme is in use (mismatched weights inject a spurious source — Sundaram & Collins 1996). The inner products are a modelling choice: with the Euclidean (counting) products the adjoint is the bare transpose Wᵀ; with L²/volume-weighted products it is M_G⁻¹ Wᵀ M_P (the immersed-boundary spreading/interpolation pair of Peskin), conserving an energy pairing rather than the plain sum.

source

The Interpolation module is the grid↔point transfer layer: interpolation (grid → point, the gather 𝓘 = W) evaluates a field at off-grid positions, and its adjoint anterpolation (point → grid, the scatter 𝓘* = Wᵀ) deposits per-point quantities back onto the grid. Both use the local high-order spline of Lalescu, Teaca & Carati (2010) via a shared LalescuSpline scheme, so they are exact transposes and conserve the deposited total (docs/ARCHITECTURE.md §10). The kernels are portable across CPU / CUDA / AMDGPU (KernelAbstractions); the point-data types live in the Points module.

Types

GBGPeriodicFields.Interpolation.LalescuSpline — Type
LalescuSpline(n, m = 1; T = Float64)

Local high-order spline interpolation scheme of Lalescu, Teaca & Carati (2010): a tensor-product of 1D weights over a compact stencil of 2n+2 nodes (neighbourhood n ≥ 0) with Cᵐ smoothness (0 ≤ m ≤ n). The per-axis weights β�q(t) for fractional cell position t ∈ [0,1) are degree-2n+1 polynomials, precomputed once into the (2n+2)×(2n+2) SMatrix coefficients (β�q(t) = Σₚ coefficients[q, p+1] tᵖ).

The interpolant is the degree-2n+1 polynomial that interpolates the central 2(n−m)+2 stencil nodes and matches, at the two bracketing nodes, the derivatives of order 1…m estimated by centred finite differences over the stencil. This reduces to Lagrange interpolation over the 2n+2 nodes at m = 0, and to the Catmull–Rom spline at n = 1, m = 1 (the default CatmullRom). It is used by interpolate (grid → point) and anterpolate (point → grid).

source
GBGPeriodicFields.Interpolation.CatmullRom — Constant
CatmullRom

The default interpolation scheme: the cubic n = 1, m = 1 LalescuSpline, a four-point C¹ stencil that reproduces the Catmull–Rom spline (and quadratic polynomials exactly).

GBGPeriodicFields.Interpolation.anterpolate! — Function
anterpolate!(field::AbstractFieldPhysical, points::PointSet, quantities::AbstractPointValues,
             scheme = CatmullRom, α = true, β = false)

Deposit the per-point quantities onto field in-place — the adjoint (transpose) of interpolate! under the same scheme — computing field = α·(Wᵀ quantities) + β·field; returns field. With β = 0 (default) the field is overwritten; with β ≠ 0 the deposit is accumulated (the common case for the two-way-coupling scatter). field and quantities must share tensor order and points must cover the same number of points. Runs as a portable atomic-scatter kernel on the field's array backend.

GBGPeriodicFields.Interpolation.interpolate! — Function
interpolate!(out::AbstractPointValues, field::AbstractFieldPhysical, points::PointSet, scheme = CatmullRom)

Interpolate field (physical-space representation) to the off-grid points, writing into out; returns out.

out must match field in tensor order and cover the same number of points as points. The transfer runs as a portable gather kernel on the field's array backend (CPU / CUDA / AMDGPU). Interpolation is defined for physical-space representation only; transform a spectral field to physical space first.

Internal API

The spline-weight generator (Fornberg finite differences + a small linear solve), the periodic cell-finding, and the in-kernel helpers — documented for contributors.

GBGPeriodicFields.Interpolation._axis_weights — Method
_axis_weights(coefficients, t)

Evaluate the per-axis spline weights βq(t) for all 2n+2 stencil nodes at fractional position t, returning an SVector. Horner over the polynomial-coefficient columns of coefficients; pure and allocation-free, so it runs inside the gather/scatter kernels on CPU and GPU.

source
GBGPeriodicFields.Interpolation._fornberg — Method
_fornberg(evaluation_point, nodes, max_order)

Fornberg (1988) finite-difference weights: weights[i, k+1] is the weight of nodes[i] in the order-k derivative (k = 0…max_order) of a function sampled at nodes, evaluated at evaluation_point. Host-side helper for the spline-weight construction.

source
GBGPeriodicFields.Interpolation._lalescu_weight_matrix — Method
_lalescu_weight_matrix(n, m)

Build the (2n+2)×(2n+2) matrix of 1D spline-weight polynomial coefficients (row q is the weight polynomial for stencil offset q − 1 − n ∈ {−n,…,n+1}; column p+1 is the tᵖ coefficient). The degree-2n+1 interpolant interpolates the central 2(n−m)+2 nodes and matches centred-finite-difference derivatives of order 1…m at the two bracketing nodes (offsets 0 and 1); see LalescuSpline.

GBGPeriodicFields.Interpolation._locate — Method
_locate(coordinate, origin, spacing, number_of_grid_points)

Return (base_cell, t) for one axis: the zero-based index base_cell of the left node of the cell containing coordinate, and the fractional position t ∈ [0,1) within it. Periodic wrapping of the stencil is applied later via mod. Pure scalar arithmetic, kernel-safe.
