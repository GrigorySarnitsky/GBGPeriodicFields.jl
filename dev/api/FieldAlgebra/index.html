FieldAlgebra

GBGPeriodicFields.FieldAlgebra — Module
FieldAlgebra

Fiberwise and pointwise algebra for the scalar, vector, and second-order tensor fields defined in Fields. Each operation comes as an allocating form — a Base or LinearAlgebra operator where one exists — and an in-place ! form. The parts are:

  • Vector-space and module operations — add! and subtract! (+, -), the weighted combination combine! ($\alpha a + \beta b$), real scaling, and scalar-field multiplication and division (multiply!, divide!, *, /). Addition, weighted combination, and real scaling are the vector-space structure; scalar-field multiplication is the action that makes fields a module over the ring of scalar fields — the algebraic sense of the word, not a Julia module: scaling a field by another field rather than by a number.
  • Contraction and product operations — dot! computes the vector Euclidean and tensor Frobenius inner products (⋅), cross! the cross product (×), mul! the tensor-on-vector action (left and right) and the tensor-on-tensor product — contracted (matrix) products, not the outer tensor product — with a five-argument α/β accumulation form and an allocating *, tr! the trace, the self-contraction of a tensor's own two indices, and det! the determinant, the tensor's third principal invariant.
  • Transposition and decomposition operations — transpose! transposes the fiber indices, and sym, skew, dev split off the symmetric, skew-symmetric, and deviatoric parts (each with a ! form).
  • Norm operations — norm! computes the pointwise absolute-value, Euclidean, and Frobenius norms.
  • Arbitrary fiber map — map! and map apply any fiber map φ you supply at every base point — a composition like exp ∘ det, a pointwise equation of state, whatever is not one of the named operations above. This is the section-valued escape hatch for un-named maps (and the sibling of the mapped reductions such as mean(det, ·)): φ may change the tensor order, and the result's order is φ's (map(det, A) gives a scalar field). A field must be in physical-space representation, since an arbitrary φ is nonlinear.

Field-field and field-constant operations preserve the representation of their arguments: they act pointwise on fields in physical-space representation and coefficient-wise on fields in spectral representation. An operation that is not linear in a field argument — multiplying two fields together, or contracting two fields — is defined only in physical-space representation, except where one factor is a compile-time constant fiber, which keeps the operation coefficient-wise; the missing combinations are deliberate.

Nonlinear results are aliased in spectral representation

A nonlinear operation — a field-field product (*, mul!, dot, cross, divide!) or a nonlinear fiber invariant (det, norm) — generates content above the grid's Nyquist wavenumber, so its result is not band-limited. The pointwise values at the grid nodes are exact, but transforming the result to spectral representation folds that out-of-band content back onto the resolved modes as aliasing error. Before feeding such a result into a spectral computation — a solver's nonlinear term — de-alias it with the sharp low-pass spectral_cutoff or the phase-shift translation_kernel from Convolution. This is the same fact that makes these operations physical-space only: a nonlinearity has no finite-band spectral form.

The mul! product follows the LinearAlgebra convention that the destination must not share storage with an input, while the index-shuffling operations (cross, transpose, sym, skew, dev) are alias-safe by construction (each fused pass reads an element's sources before writing any output) and may be called with the destination aliasing an input.

Every operation in this module is also defined for point-values (AbstractPointValues): the same fiberwise algebra applied to field values sampled at an unstructured point set. See the Points module.

Add fields, or a field and a constant, in place, and return destination.

Use this in-place form when destination is already allocated; the allocating + returns a fresh result instead.

The arguments are:

  • destination — the field that receives the sum; it shares the domain and tensor order of the operands.
  • a, b, fields... — two or more fields to add.
  • field, constant — the field-and-constant variants, in either argument order: a Real with a scalar field, a FiberVector with a vector field, a FiberTensor2 with a second-order tensor field.

Field-field addition is storage-wise and representation-preserving: it acts pointwise on fields in physical-space representation and coefficient-wise on fields in spectral representation.

In physical-space representation the constant is added at every grid point. In spectral representation only the zero Fourier coefficient changes, scaled by the number of grid points prod(grid_size), so that the physical values shift by exactly the constant.

GBGPeriodicFields.FieldAlgebra.combine! — Function
combine!(destination, α::Real, a, β::Real, b)
combine!(destination, α::Real, a, β::Real, b, kernel::ScalarFieldSpectral)

Overwrite destination with the real-weighted linear combination $\alpha a + \beta b$ of two compatible fields, and return destination.

Reach for combine! with a preallocated destination when you need a real-weighted combination of two fields in a single allocation-free pass. It fills the gap between add!, which is unit-weight ($a + b$), and multiply!, which scales a single field; the allocating equivalent is the operator expression $\alpha a + \beta b$, which builds scratch fields instead. The combination is linear and representation-preserving, so it is defined for both physical-space and spectral representation.

The arguments are:

  • destination — the field that receives the result; either input may alias it (see below).
  • α, a — the real weight and the first field.
  • β, b — the real weight and the second field.

The write is coefficientwise, so aliasing is safe without a guard temporary: a, b, or both may be destination itself. In particular combine!(u, 1, u, β, b) computes the scaled accumulate $u \leftarrow u + \beta b$ in place.

\[\texttt{destination} = \alpha a + \beta b.\]

The kernel-composed form

Passing a trailing kernel — a kernel's transfer function $\hat g$, a scalar field in spectral representation (a ScalarFieldSpectral), exactly as convolve! takes it — convolves the combination with the kernel in the same fused pass. As a real physical object the result is the kernel-weighted local average of the combination, $g \star (\alpha a + \beta b)$; in spectral representation it is one coefficientwise product,

\[\widehat{\texttt{destination}}(k) = \hat g(k) \bigl(\alpha \hat a(k) + \beta \hat b(k)\bigr),\]

replacing a combine! followed by a convolve! — one pass instead of two, saving a full read and a full write of destination per call. This form exists only in spectral representation (a kernel is a spectral object); α/β keep their combination-weight roles, and with b === destination it computes the kernel-filtered accumulate in place. The scalar kernel broadcasts over the fiber, so one method serves every tensor order, and the write stays coefficientwise — a, b, or the kernel may alias destination.

Multiply a field in place by a real number or by a scalar field, and return destination.

Use this in-place form when destination is already allocated; the allocating * returns a fresh result instead.

The arguments are:

  • destination — the field that receives the product.
  • scalar — a Real factor, accepted in either argument order.
  • scalar_field — a scalar field factor, multiplying the other operand pointwise.
  • field, constant — the operand being scaled: a field of any tensor order, or a constant FiberVector or FiberTensor2 paired with a scalar field.

Multiplication by a real number is representation-preserving and is defined for fields in both physical-space and spectral representation, in either argument order.

Multiplication by a scalar field is pointwise, so when the other factor is a field it is defined only in physical-space representation; in spectral representation the product of two fields is a convolution, which this module does not provide. The field-field result is not band-limited, so it aliases if transformed back to spectral representation; de-alias (spectral_cutoff) before spectral reuse. When the other factor is a constant FiberVector or FiberTensor2, the operation is linear in the scalar field and stays coefficient-wise, so it is defined in both representations and yields the corresponding vector or tensor field. Either argument order is accepted.

Compute a fiberwise inner product in place, and return destination.

Use this in-place form when destination is already allocated; the allocating dot returns a fresh result instead.

The arguments are:

  • destination — the scalar field that receives the contraction.
  • u, v — two vector fields, or A, B two second-order tensor fields.
  • a, B — a constant FiberVector or FiberTensor2 contracted against the field, in either argument order.

Contraction of two fields is nonlinear and is defined only in physical-space representation. \[(u \cdot v)(x) = u_i(x) v_i(x), \qquad (A : B)(x) = A_{ij}(x) B_{ij}(x).\]

Compute a fiberwise cross product (cross $\equiv \times$) in place, and return destination.

Use this in-place form when destination is already allocated; the allocating cross returns a fresh result instead.

The arguments are:

  • destination — the vector field that receives the product.
  • u, v — the two vector fields.
  • a — a constant FiberVector crossed with the field, in either argument order.

Cross products of two fields are nonlinear and are defined only in physical-space representation. In spectral representation only the cross product with a constant fiber vector (in either argument order) is provided, which keeps the operation coefficient-wise. The field-field result is not band-limited, so it aliases if transformed back to spectral representation; de-alias (spectral_cutoff) before spectral reuse.

\[\begin{gathered} (u \times v)_i = \varepsilon_{ijk} u_j v_k, \\ (u \times v)_1 = u_2 v_3 - u_3 v_2, \quad (u \times v)_2 = u_3 v_1 - u_1 v_3, \quad (u \times v)_3 = u_1 v_2 - u_2 v_1. \end{gathered}\]

Arbitrary fiber map

The escape hatch for an arbitrary fiber map that is not one of the named operations above — fields in physical representation here, point-values in Points; see map! for the physical-space-only and aliasing caveats.

Base.map! — Function
map!(φ, destination, sources...)
map!(φ, destination, source, α, β)

Apply an arbitrary fiber map φ at every base point, writing the result into destination — the section-valued companion of the mapped reductions (mean(det, A), maximum(norm, u)): where those reduce φ of the fiber over the base, this writes it as a field. It fuses in one pass, building no intermediate section, and inherits the executor's parallelism (a device kernel on a GPU, a slab-threaded loop on a CPU); being a per-point transform with disjoint writes, it is bitwise thread-count-invariant.

Use this when the operation is not one of the named fiberwise operations (det, norm, the algebra) — an arbitrary pointwise function of the fiber, a composition such as exp ∘ det included. Prefer the named operations where they exist (they carry their validity and their spectral forms); map! is the escape hatch for the unnamed, physical-only maps. Use this in-place form when destination is already allocated; the allocating map returns a fresh result instead.

At every base point x, destination's fiber is set to φ applied to the sources' fibers there; map!(φ, dest, f, g) sets it to φ(f(x), g(x)).

The arguments are:

  • φ — the fiber map, applied to the input fiber value(s) and returning the output fiber value. It must be a pure, GPU-safe function (no captured state, no scalar indexing of device arrays); its output tensor order sets destination's order (det gives a scalar field, an SMatrix-valued φ a tensor field).
  • destination — the field in physical representation (or point-value section) that receives the result; its tensor order must match φ's output.
  • sources — one or more compatible fields in physical representation (or point-value sections) sharing destination's base; φ receives their fiber values in argument order.
  • α, β — the accumulation of the single-source form, $\texttt{destination} = α\,φ(\texttt{source}) + β\,\texttt{destination}$ ($β = 0$ overwrites, the mul! convention); the variadic form overwrites ($α = 1$, $β = 0$).
Physical-space only, and the result is aliased in spectral representation

An arbitrary φ is nonlinear, so — like the other nonlinear operations of this module — map! is defined for fields in physical-space representation only, and its result carries content above the grid's Nyquist: it is aliased once transformed to spectral representation. De-alias before spectral reuse (see the module docstring). Point-value sections are representation-free and carry no such restriction.

It fuses in one pass, building no intermediate section, and inherits the executor's parallelism (a device kernel on a GPU, a slab-threaded loop on a CPU); being a per-point transform with disjoint writes, it is bitwise thread-count-invariant.

Use this when the operation is not one of the named fiberwise operations (det, norm, the algebra) — an arbitrary pointwise function of the fiber, a composition such as exp ∘ det included. Prefer the named operations where they exist (they carry their validity and their spectral forms); map! is the escape hatch for the unnamed, physical-only maps. Use this in-place form when destination is already allocated; the allocating map returns a fresh result instead.

At every base point x, destination's fiber is set to φ applied to the sources' fibers there; map!(φ, dest, f, g) sets it to φ(f(x), g(x)).

The arguments are:

  • φ — the fiber map, applied to the input fiber value(s) and returning the output fiber value. It must be a pure, GPU-safe function (no captured state, no scalar indexing of device arrays); its output tensor order sets destination's order (det gives a scalar field, an SMatrix-valued φ a tensor field).
  • destination — the field in physical representation (or point-value section) that receives the result; its tensor order must match φ's output.
  • sources — one or more compatible fields in physical representation (or point-value sections) sharing destination's base; φ receives their fiber values in argument order.
  • α, β — the accumulation of the single-source form, $\texttt{destination} = α\,φ(\texttt{source}) + β\,\texttt{destination}$ ($β = 0$ overwrites, the mul! convention); the variadic form overwrites ($α = 1$, $β = 0$).
Physical-space only, and the result is aliased in spectral representation

An arbitrary φ is nonlinear, so — like the other nonlinear operations of this module — map! is defined for fields in physical-space representation only, and its result carries content above the grid's Nyquist: it is aliased once transformed to spectral representation. De-alias before spectral reuse (see the module docstring). Point-value sections are representation-free and carry no such restriction.
