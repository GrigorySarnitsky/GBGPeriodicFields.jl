Testing — GBGPeriodicFields

This is one of three design companions: ARCHITECTURE.md explains why the package is built the way it is, PERFORMANCE.md how it performs and is benchmarked, and this one explains how the tests are built and what they must cover. Read it before adding or changing tests. The goal is not a test count — it is that every claim the package makes is checked against something independent of the package.

1. Philosophy

Verify against independent ground truth, never against the code's own other path. A test that compares one package routine to another package routine only proves they agree, not that either is correct. Two kinds of oracle are used:

  • Analytic oracles — for the differential operators. A field is taken to spectral representation, the operator applied, and the result compared to a known closed form: $\partial_x \sin x = \cos x$, $\Delta \sin x = -\sin x$, $\nabla \times (0, 0, \sin x) = (0, -\cos x, 0)$, a Helmholtz-projected field is divergence-free. These catch sign, axis, and scaling errors that a self-consistent round-trip would silently reproduce.
  • Trusted reference — for representation parity and for the GPU path. The CPU path is pinned by analytic oracles and the parity baseline; then another computation of the same quantity (the spectral form, or the same operation on a device array) is required to match it. This is still "two computations of one quantity," not a thing against itself.
  • Structural identities — relations the operators must satisfy for any input: the vector-calculus identities (div(curl) = 0, curl(grad) = 0) and, on a periodic box, the adjoint relations (divergence as the negative gradient adjoint, self-adjoint curl, a self-adjoint negative-semidefinite Laplacian, a self-adjoint idempotent Helmholtz projection). Tested on randomized band-limited fields, they pin the discrete energy/entropy structure of the scheme.

The public method set is the spec. Two mechanisms enforce this:

  • the parity baseline (test/method_parity.jl) locks the per-generic method counts (198 public methods) so a code-generation change cannot silently add or drop a method;
  • intentional-absence tests assert that invalid combinations do not exist (@test_throws MethodError), symmetrically across representations: nonlinear products are absent in spectral (field×field, division by a scalar field, pointwise norms), and the differential operators are absent in physical (differentiation is spectral-only — there are no finite-difference physical operators yet). A deliberate gap is a tested gap.

"Should work" is not done. The minimum bar for any change is: the package loads, the parity baseline and ambiguity check pass, and the suite is green.

2. Layout

  • test/runtests.jl includes each module's file inside its own wrapper module (module FieldAlgebraTests; include("fieldalgebra.jl"); end), so per-file helpers and constants (comp, plans_for, grid, T) cannot collide. Every file is also runnable on its own (julia --project=. test/<file>.jl).
  • Per-module behaviour files — fields.jl, fieldalgebra.jl, differentialoperators.jl, convolution.jl (periodic convolution + the kernel/coordinate builders spectral_cutoff / spectral_band / squared_wavenumber_field), interpolation.jl (the point-data types), pointvalues_algebra.jl (the point-value M2 + M3 surface), interpolation_transfer.jl (the physical-domain spline transfer — the smooth LalescuSpline/CatmullRom and the $C^0$ LagrangeSpline — interpolation / anterpolation kernels), transfer_spectral.jl (the spectral-domain transfer schemes — the exact DirectDFT and the fast NUFFT), and reductions.jl (the L²/measure reductions + the radial pair radial_spectrum / radial_correlation, incl. the two-field co-spectra, on fields and point-values), rdf.jl (the Phase-2 point pair-correlation: assignment_window + the FFT g(r) recipe vs direct counting), plus eltype_genericity.jl (Float64/Float32), adjointness.jl (operator structure on random fields), randomized.jl (property-based: algebraic laws on random fields / point-values / kernels), allocations.jl (a comprehensive @allocated audit, both element types: the entire in-place ! surface — spectral operators, transforms, convolve!, the M2+M3 algebra add!/mul!/multiply!/divide!/dot!/cross!/transpose!/sym!/skew! over physical+spectral, all tensor orders, the constant/α/β/reversed variants, the point-value algebra, and the spline interpolate!/anterpolate! — allocates $\sim 0$ bytes; the hot-loop reductions (physical inner, maximum, integral/mean/std/var) do not materialize a field; and the documented allocators are bounded — norm!/dev!/lpnorm/radial_* occasional, and the spectral vector inner's O(N²) Parseval-correction planes, a strided-view dot being unavailable on GPU; guards the GPU hot-loop discipline, decisions 24/25), aqua.jl (package checks), threading.jl (CPU threading; runs in both the default and a JULIA_NUM_THREADS lane), and jet.jl (JET @test_call static analysis of the public operations).
  • test/method_parity.jl — the spec-lock: per-generic method counts (the 198-method field surface and the separate 118-method point-value surface) plus detect_ambiguities (from Test) over the whole package. The explicit multiply! quartet exists precisely to keep that ambiguity set empty.
  • test/Project.toml — the test environment's dependencies, deliberately backend-free (see §5).
  • test/gpu/ — the opt-in GPU suite (see §5).
  • Doctests — the Getting-started tutorial (docs/src/tutorial.md) is written as jldoctest blocks, run and verified by doctest = true in docs/make.jl (outside Pkg.test()): a third layer of checked examples that cannot drift from the code (a wrong expected output fails the build).

3. Writing a test here

Helpers and conventions. Build fields from coordinate functions (ScalarFieldPhysical((x,y,z) -> …, grid)); take component slices with the local comp/tcomp helpers; build matching transform plans with a plans_for(field) helper that allocates the spectral scratch with similar(field_data(field), …) so it inherits the field's backend. Compare with field_data(result) ≈ expected.

Tolerances — the part that bites. ≈ (isapprox) uses a relative tolerance with atol = 0 by default:

  • For an O(1) result, bare ≈ is correct.
  • For a result that is mathematically ~zero, bare ≈ degenerates to an almost-exact comparison and will fail on nothing but rounding. Either assert maximum(abs, data) < 1e-12, or pass an explicit atol. Also choose inputs so the expected result is not accidentally zero — e.g. an axis-aligned field (sin x, sin y, sin z) is irrotational and longitudinal, so both curl and the Helmholtz projection return ~0 and test nothing. Use a field whose components depend on more than one coordinate.
  • For cross-backend comparison (GPU vs CPU), the two run the same formula and agree to roundoff, so compare with isapprox(Array(device), host; rtol, atol) carrying a small absolute floor.
  • The same trap appears for inner products of independent fields (e.g. $\langle \nabla\varphi, u\rangle$): they are near-orthogonal, so the common value of two equal inner products is small relative to the operand magnitudes. Scale the floor by the Cauchy–Schwarz product $\lVert a\rVert\,\lVert b\rVert$, not by the (tiny) result.

Pick the right oracle. Operators → analytic closed form. Representation parity and backend parity → trusted CPU reference. Never assert an operator only by inverting itself.

4. The coverage contract

For each public operation, a test must establish:

  • [ ] Physical-space correctness against an analytic or hand-computed result.
  • [ ] Spectral-space behaviour — correctness where the operation is linear in the field (valid in both representations); an asserted intentional absence (@test_throws MethodError) where it is nonlinear (physical-only).
  • [ ] Both element types — Float64 and Float32. (Float32 is the realistic GPU precision; consumer GPUs run Float64 far slower.)
  • [ ] An anisotropic domain — at least one test with $L_x \ne L_y \ne L_z$, so the $2\pi/L$ wavenumber scaling is actually exercised and a dropped length factor is visible.
  • [ ] The in-place ! form with a caller-supplied destination, including the aliasing branch for alias-guarded operations (cross, transpose, sym/skew/dev, the curl/Helmholtz wrappers) — and, for mul!, the LinearAlgebra no-alias contract.
  • [ ] Allocation-free (invariant 13): every in-place ! operator gets an @allocated assertion in allocations.jl — on preallocated buffers with a distinct destination it allocates $\sim 0$ field-sized bytes, both element types. Run on the CPU: there a materialized field's full bytes are counted, whereas GPU @allocated reports only the host wrapper of a device buffer and would miss the materialization that wedges a hot loop (the code is generic, so a CPU materialization is a GPU one). A deliberate materializer (norm!/dev!/lpnorm/std/var, the radial diagnostics, the mixed spectral inner(f, g)) instead gets a bounded guard that catches an O(N)/O(shells) regression.
  • [ ] Both α/β branches for the five-argument kernels — overwrite ($\beta = 0$, which must ignore the destination's prior contents, NaN included) and accumulate ($\beta \ne 0$).
  • [ ] GPU parity — the result matches the CPU path on a device array, under allowscalar(false).

Grid coverage. Use a mixed-parity grid (even and odd axis lengths, e.g. (8, 7, 6)) so the Nyquist split is exercised; where the Nyquist mode matters, include a field that actually populates it and confirm the derivative of a real field stays real.

5. GPU testing

GPU testing is opt-in and dependency-free for the package. The default Pkg.test() stays backend-free and portable; a GPU backend is only ever a test dependency. This is possible because the data layer is generic over AbstractArray, FFT plans are built through AbstractFFTs (dispatched on the array type), and allocations inherit their backend via similar — so a field on a ROCArray/CuArray just works.

  • Per-backend environments live under test/gpu/ (rocm/ and cuda/). Each is instantiated only on matching hardware (AMD at home, NVIDIA at the office); a no-GPU CI box never installs a vendor stack.
  • A single backend-agnostic test/gpu/suite.jl holds the test logic. A thin per-backend entry script (test/gpu/<backend>/runtests.jl) supplies to_device, device_functional, GPU_BACKEND, and calls <Backend>.allowscalar(false) before including the suite. With scalar indexing disabled, any stray scalar index into device memory inside a package method throws — turning invariant 6 into a checked guarantee rather than a convention.
  • Strategy: run the public surface on device arrays and compare against the trusted CPU result (matches, with an atol floor per §3). If no device is present the suite warns and skips.
  • Manifests are gitignored (repo convention — none are tracked); each environment reproduces from its Project.toml plus a [compat] bound, via Pkg.instantiate().

Run it on hardware:

julia --project=test/gpu/rocm -e 'using Pkg; Pkg.instantiate()'   # one-time
julia --project=test/gpu/rocm test/gpu/rocm/runtests.jl

Adding a backend = mirror rocm/ (see test/gpu/README.md); the suite needs no changes.

6. Maintenance

  • After any code-generation change, re-verify the method set is unchanged: update the counts in test/method_parity.jl only with a deliberate, reviewed reason, and keep detect_ambiguities empty.
  • Keep the test summary in CLAUDE.md (roadmap item 4) roughly current.
  • Aqua.jl (test/aqua.jl) runs Aqua.test_all on every Pkg.test() — ambiguities, unbound type parameters, undefined exports, project/compat consistency, stale deps, type piracy, persistent tasks. Keep it green; among other things it enforces that every dependency carries a [compat] bound.
  • JET.jl (test/jet.jl) runs @test_call on the public operations, filtered to the package's own modules — a per-Julia-version static check for inference-detected errors (MethodError, BoundsError, undefined variables). It is left uncapped in test/Project.toml so each CI Julia version resolves a compatible JET. Note it analyzes the running version, so it does not catch version-divergence (that is the CI matrix's job).
  • CI (.github/workflows/CI.yml) is manual-only — workflow_dispatch plus release tags, not every push: each commit is authored locally and the full matrix is run before pushing, so a push-triggered run would only re-verify what is already green (a tagged release additionally exercises a from-scratch clean-environment resolve, the one thing a single local run cannot give). The matrix is Julia 1.11 (the compat floor) at -t1 and current stable at -t4. Running both lanes locally needs a per-version resolve — the gitignored top-level Manifest.toml is Julia-version-specific, so a stable-resolved manifest makes julia +1.11 … Pkg.test() error (manifest generated by a different version); clear it so 1.11 resolves fresh, then restore the stable one (CI sidesteps this, resolving from scratch per job).
  • Performance is tracked separately, not by Pkg.test(): the opt-in benchmark/ suite and its coverage contract live in PERFORMANCE.md (the third design companion).

7. Current coverage and known gaps

Honest status, so the contract above reads as the target rather than a description.

Covered: FFT round-trips; spectral multipliers cross-checked against AbstractFFTs.fftfreq/rfftfreq; the Nyquist split both at the multiplier level and end-to-end (the derivative wavenumber zeroed vs the squared wavenumber kept at the Nyquist mode); M2 + M3 algebra and contractions in both representations; the spectral zero-mode constant invariant; the point-value algebra — the Points module's M2 + M3 mirror of the physical field surface (storage-wise broadcasting), checked per-point on CPU across Float64/Float32 (test/pointvalues_algebra.jl) with the point-data types in test/interpolation.jl; the in-place ! forms with caller-supplied destinations and the alias guards (cross!, transpose!, sym!/skew!/dev!, curl!, helmholtz_projection!); the intentional absences in both representations (nonlinear products absent in spectral, differential operators absent in physical) and the physical/spectral symmetry of every linear field/fiber operation; the differential operators by analytic round-trip, including an anisotropic $(2\pi, 4\pi, 6\pi)$ box that exercises the $2\pi/L$ wavenumber scaling; the vector-calculus identities div(curl u) = 0 and curl(grad φ) = 0; element-type genericity on CPU (Float64 and Float32, asserting element-type preservation through operations); the 198-method field and 118-method point-value parity baselines and zero ambiguities; Aqua.test_all (ambiguities, unbound type parameters, undefined exports, Project/compat consistency, stale dependencies, type piracy, persistent tasks); the operator adjoint/structural identities on randomized band-limited fields — divergence as the negative gradient adjoint, self-adjoint curl, a self-adjoint negative-semidefinite Laplacian (with the dissipation identity), and a self-adjoint idempotent Helmholtz projection — with the L² inner product computed inline (the global L² inner now lives in the Reductions module, below); and GPU parity on ROCm across Float64 and Float32 (allowscalar(false)) — the public field surface (including the mul! $\beta = 0$ / $\beta \ne 0$ branches), confirmed on an AMD Radeon, plus the PointValues algebra, the interpolation / anterpolation transfer (gather, atomic scatter, accumulate, plus a heavy atomic-contention case), the spectral transfer (DirectDFT and NUFFT), convolution (apply a Fourier kernel), and the L²/measure reductions added alongside; and CPU threading — every threaded assignment is bitwise-identical to serial (field ops, the codegen contractions/products including mul!'s $\beta=0$/$\beta\ne0$ branches, transpose/sym/skew/dev, norms, and the differential operators), exercised in both the default and a JULIA_NUM_THREADS=4 lane (test/threading.jl), with the override / cutoff gate and the GPU materialize! fallback also asserted; and the L²/measure reductions (test/reductions.jl): integral/mean/inner/l2norm/lpnorm/std/var/maximum on physical fields and point-values, against analytic oracles ($\langle \sin\rangle = 0$, $\langle \sin^2\rangle = \tfrac12$) and manual references, across Float64/Float32, with the arithmetic-mean semantics on both bases ($\tfrac1N\sum$ grid, $\tfrac1M\sum$ points), the extensive/intensive $\mathrm{integral} = \mathrm{measure} \cdot \mathrm{mean}$ relation (incl. an anisotropic box), the energy identity $\tfrac12\,\mathrm{inner}(u,u) = \tfrac12\langle |u|^2\rangle$, the spectral Parseval inner/l2norm (equal to the physical inner, scalar/vector/tensor, on even-$N_x$ and odd-$N_x$ grids to hit both the Nyquist and no-Nyquist branches), the shell-resolved Parseval inner radial_spectrum (the radial power spectrum, checked by the exact refinement $\sum_\kappa E(\kappa) = \langle f, f\rangle$ over scalar/vector/tensor on even-$N_x$ and odd-$N_x$ grids, plus the single-mode shell placement and its spectral-only absence), its physical-space dual radial_correlation (the Wiener–Khinchin two-point autocorrelation, checked against an independent binned-circshift autocorrelation and $C(0) = \mathrm{inner}(f,f)$, all orders / both grids), the two-field co-spectra radial_spectrum(f, g) / radial_correlation(f, g) (the cross-power / cross-correlation, refining the mixed inner(f, g): analytical oracles — an orthogonal pair $\cos x \perp \sin x$ ⇒ zero, and $\cos x \pm \cos 2x$ ⇒ $\pm\tfrac12$ in adjacent shells cancelling to $\mathrm{inner} = 0$ (the co-spectrum may be negative); the $f \leftrightarrow g$ symmetry; the $g = f$ reduction to the single-field forms (bit-identical); and an independent binned-circshift cross-correlation on a random pair — scalar/vector/tensor, both grids; the shared $|k|$/$|r|$ shell binning is a single scatter-add pass — KernelAbstractions / Atomix, device-clean, no scalar indexing (decision 25) — so these oracles plus the GPU parity suite also cover that histogram kernel), and the intentional absence of the measure reductions on spectral fields; and convolution (test/convolution.jl): periodic convolution as the coefficientwise product $\hat f \cdot \hat g$ with a ScalarFieldSpectral kernel, checked against the translation kernel $\exp(-i k_a m \Delta)$ (a shift of $m$ cells, grid spacing $\Delta$) $\Leftrightarrow$ circshift along all three axes, on scalar and vector fields (an independent physical oracle), the identity / scaling / cutoff kernels over scalar, vector, and tensor (R=2) fields (the 5-D fiber broadcast), sharp-cutoff idempotence, kernel-composition associativity, the α/β accumulate form (incl. R=2), in-place aliasing safety, a mixed-parity (8,7,6) grid (odd axis + Nyquist), the spectral_band annular band-pass (spectral_cutoff = band(0,k), idempotent, a $|k|^2$ membership oracle) and squared_wavenumber_field (the $|k|^2$ radial coordinate vs the analytic sum, real-valued), across Float64/Float32, and the physical-space intentional absence on physical fields; the point pair-correlation (rdf.jl, decision 22 Phase 2): assignment_window against its $\prod \operatorname{sinc}^2$ formula, and the FFT g(r) recipe (anterpolate density → deconvolve → radial_correlation) validated against an independent direct $O(M^2)$ physical-space pair count on a clustered set (the clustering peak within ~10% and the g → 1 baseline); and property-based tests (randomized.jl): algebraic laws on random fields, point-values, and kernels over several trials — vector-space and contraction/product identities, transpose/sym/skew/dev, the reduction laws (inner symmetry, linearity, Cauchy–Schwarz, $\mathrm{integral} = |\Omega|\cdot\mathrm{mean}$), convolution bilinearity/commutativity, and the operator identities $\nabla\cdot(\nabla\times u)=0$, $\nabla\times(\nabla \varphi)=0$ — which catch the index/sign bugs that specific analytic functions can mask.

Gaps:

  1. Docstring doctests — the Getting-started tutorial is doctested (§2, the third checked layer), but the per-function docstrings in src/ do not yet carry their own jldoctest examples.
  2. Even-broader randomized coverage — randomized.jl now covers the algebra, reductions, and convolution laws on random CPU data; extending property checks onto the device, and to more element types, is possible but lower-value (the laws are formula-level and backend-independent).
